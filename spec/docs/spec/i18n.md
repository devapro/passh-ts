# Appendix: languages

Normative appendix to [spec.md](../../spec.md) §3.3 (`language`). Scope: how the language is chosen, what is translated and what never is, plural rules, answers to questions, and how errors from lower layers come out in the language. Precedence: see [spec.md §1.1](../../spec.md#11-appendices-normative).

**What binds a re-implementation.** Byte-identical output is required only for `language = "en"`: the English texts given in spec.md and the appendices (except where an appendix says otherwise, such as the TUI's on-screen texts, [tui.md](tui.md)). For `ru` and `sr` the normative parts are:

- which outputs are translated and which stay the same in every language (§3);
- the plural rules (§4) and the yes/no hints and answers (§5);
- the **glossary** of [docs/translations.md](../translations.md#glossary): one English term, one translation everywhere;
- the fixed strings the appendices give in all three languages: the sheet frame strings, including the translated comment of the third recovery command ([print.md §8](print.md#8-sheet-frame-strings)).

Not normative: the wording of every other `ru` and `sr` text. The reference's catalogues (`internal/i18n`) are one valid translation; another that uses the glossary terms is compatible. The rest of docs/translations.md (style, verb forms, the Printer API, catalogue files) is a contributor guide for the reference, not specification.

Related: [print.md](print.md) §8 (sheet frame strings in all three languages), [cli.md](cli.md) (help, error output, exit statuses), [tui.md](tui.md) (TUI texts).

## 1. Values

| `language` | Language | Notes |
|---|---|---|
| `en` (default) | English | the source texts |
| `ru` | Russian | |
| `sr` | Serbian, Latin script, ekavian | never Cyrillic |

The value must be exactly one of these strings (case-sensitive, no blanks): `EN`, `Ru`, ` ru`, `sr-Latn`, `de`, `""` are errors. An invalid value makes the config file fail to load like any invalid key: `passh: config <path>: language: "de" is not one of "en", "ru" or "sr"`, exit 1, in English (§2).

## 2. Choosing the language

The language is fixed once per process, **before** the command line is parsed, because help texts are built in it:

1. If the first argument is the agent's internal child command (`__agent`, agent-session.md): English. The agent loads no config; what it sends to clients is English text that the client translates (§6).
2. Scan the arguments up to a `--` argument for `--config X`, `--config=X`, `--vault X`, `--vault=X`; the last of each wins (`--configx`, `--vault-x` are not matches).
3. Resolve and load the config exactly as a command would (spec §3.3: `--config`, then `$PASSH_CONFIG`, then `$XDG_CONFIG_HOME/passh/config.toml`), with `--vault` overriding `vault`.
4. Loaded → its `language` (default `en` when the key is absent). Any failure → English: no config file, unreadable, invalid TOML, an unknown key, an invalid value (including `language` itself), or a missing `vault` without `--vault`.

Consequences: with `--vault` and a loadable config file, the config's language is used; with `--vault` and no config file, English. A broken config file makes every message of that run English, including the report of the config problem when the command loads the config. `passh init` runs in the language of an existing config file, else English; the config file it writes says `language = "en"`.

## 3. What is translated

Everything written **for people**, in the chosen language:

- status lines, confirmations, notes and warnings on stderr (the `passh: ` prefix stays; `warning: ` is translated: `passh: предупреждение: …`);
- prompts and their explanations on the terminal, the `[y/N]` hints (§5);
- error messages (§6), including the usage hint `Run 'passh --help' or 'passh <command> --help' for usage.` and pflag's parse errors (`unknown flag: --x`, `flag needs an argument: …`, `invalid argument … for … flag: …`, `bad flag syntax: …`);
- `--help`: command summaries and descriptions, flag descriptions, the headings (`Usage:`, `Aliases:`, `Examples:`, `Available Commands:`, `Additional Commands:`, `Flags:`, `Global Flags:`, `Additional help topics:`), `(default %s)`, `(DEPRECATED: %s)`, the closing `Use "… [command] --help" …` line, the `help` command's texts and the `-h`/`-v` flag descriptions;
- the TUI, the built-in form, `doctor` (its report on stdout too), the prose of `verify` and the import report;
- the text sheet, the recovery key sheet and the print page: titles, headings, prose, legend, `CONFIDENTIAL`, `page N of M`, `printed …`, the entry count, `(top level)`, `(continued)`, the shell comment of the third recovery command, the page's tip, the QR code's `aria-label`, the print page's error bodies (421, 405, 410), the certificate notice, the skipped-address list and the result line (print.md §8).

The **same in every language**:

- data on stdout that scripts or passh read: `ls`, `find`, `tags`, `show` and the entry text form, `export`, `generate`'s password, the `backups` listing, `--version` (`passh <version>`);
- names: commands, flags, entry field names (`password`, `username`, `url`, `tags`, `notes`, custom keys, also as labels on sheets), config keys and values, `vault_id`, file names, cobra `Use` lines and placeholders (`<path>`, `[command]`, `[flags]`, `<file>`);
- the typed confirmation phrases `PRINT RECOVERY KEY`, `EXPORT PLAINTEXT`, `PRINT`, and the English yes/no answers (§5);
- exit statuses; the HTTP headers, the CSP, and the print page's 404 body (`404 page not found`);
- vault values, `age1…`, `AGE-SECRET-KEY-1…`, SHA-256 fingerprints and sums, revisions (`r42`), the ambiguity mark codes `D U L S`;
- formats: dates `YYYY-MM-DD HH:MM` (and `YYYY-MM-DD` in certificate notices), Go durations (`30s`, `5m0s`, `1h30m`), byte sizes as `doctor` writes them (`256 MiB`), ASCII digits without grouping; sorting is bytewise, never locale collation (the TUI writes whole hours and minutes with translated units, tui.md);
- text from the operating system or a library: `open /x: permission denied`, `time: invalid duration "x"`, TLS and network errors.

Layout follows the translated text: columns on the sheets are counted in display width (print.md §3.2), the help's flag column, `doctor`'s columns and the `tags` listing in characters (code points of the escaped text), never in bytes. A translated text may be longer than the English one; nothing is truncated.

## 4. Messages and plurals

The English text is the key. A translation is looked up per message; a message without a translation is shown in English (so a partial catalogue degrades message by message). A message with arguments is formatted like Go's `fmt.Sprintf`; translations may reorder arguments with indexed verbs (`%[2]s … %[1]d`) and must use the same verbs for the same arguments. A message without arguments is literal text (a `%` in it is printed as is). Where one English text needs two translations, the key is `context` U+0004 `text`; without a translation for that context the English text is shown (not the context-free translation).

Arguments are rendered in the language too: an argument that is an error goes through §6, a value that describes itself (a print page result, a rollback status, a passphrase-strength verdict, a clipboard method, …) is rendered in the language; other values (numbers, paths, names) are formatted as is. `%w` is rendered as `%v`.

Plural forms (CLDR rules for integers; `n` is taken as its absolute value):

| Language | Forms | Rule |
|---|---|---|
| en | one, other | one iff n = 1 |
| ru, sr | one, few, many | one: n mod 10 = 1 and n mod 100 ≠ 11; few: n mod 10 ∈ 2…4 and n mod 100 ∉ 12…14; many: everything else |

| n | 0 | 1 | 2 | 4 | 5 | 11 | 12 | 14 | 21 | 22 | 25 | 101 | 111 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| ru/sr form | many | one | few | few | many | many | many | many | one | few | many | one | many |

Example: `1 запись, 2 записи, 5 записей`; `1 stavka, 2 stavke, 5 stavki`. A plural message missing from a catalogue falls back to English one/other (one iff n = ±1).

## 5. Answers and typed phrases

Yes/no questions show the hint in the language; the capital letter is the default (an empty answer):

| Language | default no | default yes |
|---|---|---|
| en | ` [y/N] ` | ` [Y/n] ` |
| ru | ` [д/Н] ` | ` [Д/н] ` |
| sr | ` [d/N] ` | ` [D/n] ` |

Accepted after trimming blanks, in any letter case:

| Language | yes | no |
|---|---|---|
| every language | `y`, `yes` | `n`, `no` |
| ru, additionally | `д`, `да` | `н`, `нет` |
| sr, additionally | `d`, `da` | `ne` (`n` is already accepted in every language; docs/translations.md lists `n`, `ne`: the same set) |

The words of one language are not accepted in another (`da` is not an answer in `ru`). Anything else prints `Please answer y or n.` (translated) and asks again; after 3 answers that are not understood the question fails with `not confirmed`.

The TUI's one-key questions (delete, rollback; [tui.md](tui.md) §7.6, §9) are not these prompts: in every language they show `[y/N]` (or `y/N`) untranslated and take only `y`/`Y` as yes.

Typed phrases (`Type PRINT RECOVERY KEY to confirm: `; only the prompt sentence is translated) are compared after trimming surrounding white space, case-sensitive, never translated. Wrong → `not confirmed: you didn't type <phrase>`; end of input → `not confirmed: no answer`.

## 6. Errors in the language

Errors are made in English by the lower layers (vault, keys, config, agent, …) and rendered in the language only when shown. Rendering an error `e` (English: always `e`'s English text, unchanged):

1. `e` describes itself in a language (passh's own errors: sentinels, formatted errors, typed errors with fields) → that rendering. A formatted error looks up its format string, then renders its arguments by §4 (wrapped errors recursively). Example: `/v: неверная парольная фраза или повреждён блок ключа` for English `/v: wrong passphrase, or the key block is damaged`.
2. Otherwise, if `e`'s whole English text is a catalogue key → its translation. This is how texts that crossed a process boundary as plain strings are translated: the agent's refusals (`malformed request`, `request too large`, …) are sent as English keys and translated by the client.
3. Otherwise, if `e` wraps one error and its text ends with that error's text (`context: cause`) → the context unchanged + the cause rendered by these rules.
4. Otherwise, if `e` joins several errors and its text is exactly their texts joined by line breaks → each rendered, joined by line breaks.
5. Otherwise `e`'s text unchanged (OS and library errors).

The rendered text is then escaped for the terminal (S4) and printed as `passh: <text>`. A config problem that prevents loading is shown in English (§2), and so is the reason an invalid `language` value is refused.

## 7. HTML

The print page's `<html lang>`: `en`, `ru`, `sr-Latn`. The page and the sheet on it are in the same language; the HTTP headers and markup are identical in every language (print.md §6.8).
