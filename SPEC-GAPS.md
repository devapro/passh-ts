# SPEC-GAPS — where the passh spec forced a guess, or was wrong or contradictory

Collected while building passh-ts from `spec/` alone (clean room), and checked against the
reference binary run as a black box (`reference/passh-go`, 0.1.0-ref). Each item: the section,
the issue, and what passh-ts does. "Reference:" means the behaviour was observed on the
reference binary and reproduced; "Decided:" means nothing told us and we chose.

Audit items (`spec/docs/reviews/2026-11-16-spec-audit.md`, `#n`) note whether passh-ts keeps the
current behaviour or implements the proposed fix.

## Vault file, keys, crypto (vault-format.md)

1. **§2.2 steps 4 and 6, warnings about ignored text.** The spec writes `ignored N line(s) of text…`; the reference prints proper plurals (`1 line`, `2 lines`). Reference reproduced (and the text is a plural message for translations).
2. **§2.2 step 3, container version too large for an int.** The spec says it "counts as newer" but not what number the message shows. Reference: `made by a newer passh; upgrade passh (container version 9223372036854775807)` (the int64 maximum). Reproduced.
3. **§2.2, warnings on a failed parse.** Not said whether the "ignored lines" warnings are printed when the parse then fails. Reference (`verify`): none. The parser returns them with the error and the caller decides.
4. **§3.6 "Damaged key block", unusable last block.** Not said what happens when the last armored block can't be used either. Reference: no END line, bad base64 or an empty block → the block-1 error without the warning; otherwise the warning, and any decryption failure of that block (header, wrong key, payload) is reported as the block-1 error. Reproduced.
5. **§3.2 step 2, work factor above 2^63−1.** Marked non-normative (platform integer); passh-ts behaves as a 64-bit build (falls to step 3).
6. **§3.2 step 4, "plaintext longer than 4096 bytes".** Read as a size-limited read: decryption fails as soon as an authenticated chunk takes it past 4096 bytes. Not observable on the reference.
7. **§2.5 / audit #3, saves over 64 MiB.** Proposed fix implemented; the spec gives no text, so: `the vault file would be N bytes, larger than 64 MiB, which passh can't open; nothing was saved`.
8. **§3.5 passphrase strength reasons.** Non-normative, but for compatibility: the reference words the reasons for the `us_tv_and_film` and Wikipedia lists as "a word by itself…" / "common words are easy to guess", unlike zxcvbn's own feedback; matched. `it is empty or too short` couldn't be triggered on the reference (mapped to an empty match list). passh-ts uses the original `zxcvbn` 4.4.2 (the reference uses the Go port trustelem/zxcvbn); on 36 probed passphrases score and reason matched.
9. **storage §3.2 step 2 "a data block whose age header this key unwraps (header only)".** Taken literally: the stanza unwrap is tried, the header MAC is not verified.
10. **i18n of container errors.** The spec gives whole English sentences; for translation they are composed as `file is damaged (block %d): %s` / `file is truncated: %s` with each reason a separate catalogue key.

## Files, config, OS (storage.md, agent-session.md §A2.1–A2.2, §A8)

11. **storage §1.4, busy lock without a specific text.** The spec has texts only for the vault lock. Decided: `another passh process has held <path> for 15s` for the generic case; callers use the spec's text where there is one.
12. **storage §1.4, `fchmod` on lock files.** The tolerated errnos are listed only for temporary files. Decided: the same tolerance (EPERM, EINVAL, ENOTSUP, EOPNOTSUPP) for lock files; others fail as `chmod <p>: …`.
13. **storage §1.4, cleaning leftovers, a flock error other than "busy".** Unspecified. Decided: fail with `locking <file>: …` and keep the file.
14. **storage §1.4, cancelled lock wait.** The text after `stopped waiting for another passh process: ` is unspecified. Decided: Go's `context canceled` (or the cancelling reason).
15. **storage §0, errors of the real-path computation.** No texts given. Decided: Go's `filepath.EvalSymlinks` texts (`lstat <p>: …`, a bare `not a directory`, `EvalSymlinks: too many links` after 255 links).
16. **storage §2.2, TOML decoder strictness.** The spec requires TOML 1.1.0 and calls the decoder's messages non-normative. passh-ts has its own strict TOML 1.1 parser (smol-toml loses key order and line numbers, both needed for the unknown-key list). Strict TOML refuses a few invalid documents that BurntSushi/toml v1.6 accepts (reopening a dotted-key table with a header; extending an inline table with `[x.b]`).
17. **storage §2.2, several type errors.** The reference reports one of them at random (Go map order); passh-ts the first in file order.
18. **storage §2.2 step 3, which unknown keys are listed.** "Only the table" for an unknown table is underspecified. Reference: an unknown key is not listed when an earlier listed unknown key is a proper prefix of it, but `[aaa.b]` then `[aaa]` lists both and `[[zzz]]` twice lists `zzz` twice; dotted keys list the full dotted path, an inline table only the table; names are quoted with BurntSushi's `Key.String` and then `%q`. Reproduced.
19. **storage §2.1 / cli.md §1.2, texts the spec doesn't give.** Reference reproduced: `--vault: $HOME is not set`, `--config: …`, `$PASSH_CONFIG: …`, the problem line `vault: $HOME …`, `config: read <p>: is a directory`; only ENOENT counts as a missing config file (a dangling symlink is missing; EACCES and ENOTDIR are errors even with `--vault`); an empty `$HOME` counts as unset.
20. **agent-session §A2.1, no computable state folder.** With `$HOME` unset and no absolute `$XDG_STATE_HOME` the spec is silent. Decided: the error `$HOME is not set`.
21. **storage §1.3 mkdirs, existing components.** Checked with `stat`, so a symlink to a folder counts as a folder (the spec says "existing folders are never changed or checked").
22. **Audit #9** (`renameNoReplace` fallback, failed unlink after a successful link): fix implemented (warning, the rename counts as done). **#11** (config folder/file modes reduced by the umask): current behaviour kept, as storage.md §1.2 says. **#24** (`PR_SET_DUMPABLE`): not set, as §A8 says nothing else changes. **#25** (`$TMPDIR` re-read for the socket fallback): current behaviour kept.

## Data, text form, paths, escaping (vault-format.md §4–§6, agent-session.md §A9.1, cli.md fuzzy)

23. **vault-format §4.2–§4.4, order of checks and the texts of decoding errors.** The spec gives the messages but not the order in which they are found, nor the prefixes of type errors. Reference (probed with crafted data blocks), reproduced: known members are read in a fixed order regardless of input order (top: format, version, vault_id, revision, saved_at, entries, deleted; entry: id, path, password, username, url, tags, fields, notes, created_at, updated_at); type errors carry the member path but no position (`entries: path: invalid path: …`, `entries: tags: json: cannot unmarshal number into .1 of type string`); every entry's content checks come before `missing vault_id`, which comes before missing/duplicate ids and paths, which come before tombstones; tag errors read `entry N: invalid tag …` (no `invalid entry:`); a bad field value reads `field pin must be a single line` (key unquoted); vault_id missing or of a wrong type → `missing or bad vault_id`, `null` or `""` → `missing vault_id`; a null or missing path → `missing path`, `""` → `entries: path: invalid path: it is empty`.
24. **vault-format §3.3 "the parser's own text".** Declared non-normative, but scripts and tests see it; passh-ts reproduces Go's encoding/json texts (`json: cannot unmarshal array into Go value of type map[string]jsontext.Value`, `invalid character '\x01' in string`, ``invalid escape sequence `\q` in string``, `… in numeric literal`, `exceeded max depth`, invalid bytes shown as `'\xff'`). A re-implementation in another language has to emulate Go's JSON library to match — the spec should either fix these texts or say plainly that tests must not compare them.
25. **Audit #31 (§4.6, invalid UTF-8 inside unknown values).** Proposed fix implemented: one U+FFFD per invalid byte; the reference copies the bytes.
26. **Audit #32 / §4.7 (revision 2^64−1).** Proposed fix implemented: the save is refused (`revision-max`, own text); the reference wraps to 0.
27. **Audit #36 (`mv` of a folder onto a destination the same move frees).** Current behaviour reproduced (`mv m/b m` fails with `m/b/x: already exists`).
28. **Audits #18, #37, #38 (search ranking, NFC of the query).** Current behaviour reproduced (TUI ties by plain byte order, query not normalized); the fixed variant exists behind an option.
29. **vault-format §5.3 vs import-export §1.6 — contradiction.** §5.3 says "a second username line among them becomes a custom field"; import-export §1.6's table says a second `username` goes to the notes while a second `user`/`login` becomes a field. passh-ts follows §1.6 (the more specific table). A metadata line moved to the notes loses the trailing CR it lost when tested as metadata.
30. **Lone surrogates.** JS strings can hold lone surrogates that UTF-8 can't; S4 escapes their WTF-8 bytes (U+D800 → `\xed\xa0\x80`) and validation reports `<name> is not valid UTF-8`. (A Go implementation never meets this case.)
31. **print.md §3.2 display width.** Widths are defined only for text after S4 escaping; control characters count 1. Unassigned code points take the EastAsianWidth.txt defaults (W in the CJK blocks and planes 2–3). The spec pins Unicode 15.0.0; JS engines ship newer, mixed tables (Bun: NFC from ICU at Unicode 17, regexp property tables of another version), so passh-ts generates its own 15.0.0 tables for categories, case folding, White_Space and width, and relies on the engine only for NFC (stable for code points assigned in 15.0).
32. **Checks only reachable for data built in memory** (a path not in NFC, an unnormalized tag, editing a missing id): own texts.
33. **Small decisions.** `parseTagList` de-duplicates; the data operations NFC-normalize paths themselves (matters for U+212A KELVIN SIGN, which NFC maps to `K` — found by interop); time errors Go-quote the value (`saved_at: bad time "a\tb"`), as the reference does.

## Terminal, prompts, clipboard, editor, processes (agent-session.md §A4–§A7)

34. **§A4, CRLF in separate prompts.** "An LF right after a CR that ended the previous line is skipped" — the reference applies it only within one masked multi-line read; each prompt (both prompts of a pair too) starts fresh, so a pair pasted with CRLF mismatches. Reference reproduced.
35. **§A4, masked input limit.** Reference: the limit for each line is 65535 minus (length + 1) of every finished line, the error `input longer than <that> bytes`. Reproduced.
36. **§A4, plain (cooked) lines over 64 KiB.** No text given; decided `input longer than 65536 bytes` (unreachable in canonical mode on Linux).
37. **§A4, cooked prompts.** Unspecified details, reference reproduced: a signal at a cooked prompt writes no line break (`Username: ^Cpassh: …`); Ctrl-D after text returns the text and end of input isn't sticky; end of input at a yes/no question is a bare `EOF` (`passh: EOF`, like audit #41).
38. **§A4 pairs.** An empty first answer uses one of the 3 attempts; after 3 the error is `passphrases don't match` even if no mismatch occurred. Reference reproduced.
39. **§A4, ESC sequences.** `ESC [` / `ESC O` followed by a byte outside the specified ranges is not covered. Decided: the sequence ends and the byte is handled normally (so CR still ends the line). Masked input echoes one `*` per non-continuation byte of invalid UTF-8.
40. **§A5, the `<method>` text.** Reference: `command %q` of the argv joined by spaces after single-line S4 escaping (so `\t` shows as `\\t` inside the quotes). Reproduced.
41. **§A5 / cli.md §2.6, `copy --field ""`.** The hint names the field; the reference's hint says `--field password` for an empty field name. (CLI: reproduced.)
42. **§A6 vs cli.md §2.8 — order of checks contradicts.** cli.md §2.8: "with `--editor`, the editor is looked up before unlocking … without a tmpfs base, note … and the form is used". Reference: the tmpfs base is checked first, and without a tmpfs `$EDITOR` is never looked up. Reference order implemented.
43. **§A6, the no-tmpfs reason text** isn't given. Reference: `no tmpfs for the temporary file (checked $XDG_RUNTIME_DIR (<v>) and /dev/shm): the entry would be written to disk in plain text; use the built-in form (passh edit without --editor)` (or `(checked /dev/shm)`). macOS wording not observable; decided `(passh looks for one only on Linux)`.
44. **§A6 details from the reference**: the unknown-editor warning names the base name of the first word; `/dev/shm` is checked with `stat` (follows symlinks), `$XDG_RUNTIME_DIR` with `lstat`; the editor failure names the resolved path (`the editor failed (/abs/vim: exit status 1); …`); after "no" to `Edit it again?` the error is the validation error itself (the CLI adds `nothing was saved: `); a cleanup failure on top of another error: both joined; a signal at `Edit it again?` → 128+n.
45. **§A7, lookup and failure texts.** Go's `os/exec` texts (`exec: exec: "x": executable file not found in $PATH`, `stat ./x: no such file or directory`, `cannot run executable found relative to current directory`); clipboard command failures `clipboard command: <argv0>: exit status 4`, timeouts `…: signal: killed`. Reproduced; a non-Go implementation must emulate them.
46. **Audit #1** (sleep stops the TUI idle and clipboard timers): fix implemented in the clipboard wait (deadline checked by wall clock and monotonic clock). **#27** (no OSC 52 size limit) and **#41** (bare `EOF`): current behaviour kept.
47. **Reference bug found:** `passh-go recover` panics (Go stack trace, exit 2) on a 65535-byte line followed by a blank line at the `> ` prompt. passh-ts reports `input longer than …`.

## Printing and the print page (print.md)

48. **print.md §5, line widths of the recovery commands — documentation bug.** It says only the two `tr … | awk …` lines exceed 80 columns, but the third command with its comment is 87 columns (in the reference too). Actual behaviour kept.
49. **print.md §2.4, notes that are only white space.** Left out of the sheet (reference behaviour, verified); the spec should say so.
50. **print.md §6.7, a stop while the page is being written.** Unspecified what the TTL, Esc or a cancellation does mid-response. Decided: result "cancelled" with the client named; a 30 s write wait running out → "failed" with `(i/o timeout)`.
51. **print.md §6.2, "an address with a zone is refused".** Has no effect on interface addresses (only link-local addresses carry zones, and those are refused anyway). Reference: an interface listed twice in `print_web.interfaces` reports its skipped addresses twice; reproduced, not in the spec.
52. **print.md §6.3/§6.6, "case-insensitive" host names.** Implemented as Unicode simple folding (Go's `EqualFold`).
53. **print.md §6.3, order of the certificate's SANs.** Unspecified; reference: DNS names first, then IPs in bind order. Reproduced.
54. **print.md §6.8–§6.9, QR codes.** The spec says only that the encoder picks the smallest version. The reference (skip2/go-qrcode) also mixes segments (byte, numeric, alphanumeric) and scores masks with its own non-standard penalty. passh-ts reproduces both, so the QR codes are identical; a plain encoder would give different (valid) codes — the spec should say whether byte-identity extends to the QR modules.
55. **print.md §4.2, `(continued)` copies of a header** aren't re-wrapped (as in the pseudo-code), so they can exceed 80 columns. Reproduced.
56. **print.md §3.4, "hard-wrapped at 78" for long labels** means chunks of 78 columns each prefixed by 2 blanks (verified on the reference).
57. **print.md §6.9, keys in the dialog.** Any ESC byte stops the dialog, so an arrow key does too (decided; not checked on the reference).
58. **HTTP answers before the §6.6 table** (non-normative, but observable): Go's net/http texts reproduced (`400 Bad Request: missing required Host header`, an `HTTP/1.0` status line for 1.0 requests, `OPTIONS *` → 200, Go's 2048-byte chunking). passh-ts has its own small HTTP/1.1 layer to match these.
59. **Spec §14 Q4 (`allow_from`).** Current behaviour: a non-empty `allow_from` replaces the default ranges; any CIDR accepted, `0.0.0.0/0` included. **Audit #21, #22, #23**: current behaviour kept.
60. **cli.md §2.17, no terminal.** The text isn't given for `recovery-key print` specifically; the generic `passh <cmd> needs a terminal (over SSH: use \`ssh -t\`)` is used.

## TUI and the built-in form (tui.md)

61. **Audits #1, #17, #18, #19 (TUI).** Proposed fixes implemented: the idle lock counts the larger of monotonic and wall-clock time (#1); "Reloaded: your input is back…" in the normal style (#17); search ties ordered by path segments (#18); Ctrl-C while typing a search closes it like Esc instead of quitting (#19). **#30** (TUI passphrase input differs from the CLI prompt): current behaviour kept.
62. **tui.md §3.2/§7.2–§7.5, cancelling a prompt.** No message (as the reference); the form's cancel shows "Cancelled.".
63. **tui.md §10.2, "one message" on the lock screen.** Joined with spaces (reference), in the error style if any part failed; "Clearing the clipboard failed: …." keeps its period there but not in the copy status of §7.1, following the spec's text in each place.
64. **Texts the spec doesn't give** (decided): "Paste refused: the text isn't valid UTF-8." (lock screen, prompts, search), inline "paste refused: the text isn't valid UTF-8" (form), "Busy: wait for the print page to start.", "<path>: not found" under a kept prompt whose entry was deleted on disk, "Type the passphrase, then Enter." when the agent hint was shown but the agent has gone.
65. **Unspecified key handling.** With the detail open, keys that are neither global nor detail keys are ignored.
66. **tui.md §9, rollback "no" at unlock.** It closes the session without stopping the agent (not a lock); Ctrl-C there counts as quitting, which is a lock (stop_agent applies).
67. **tui.md §6.2.** The whole entry view is stacked when any label is wider than 8 cells (decided). §3.3 help: the reference's key list (no PgUp/PgDn/Home/End lines), notes wrapped at 44 cells. §11.1/§11.6: the form's status line takes a row only when it has text; opening a form clears the TUI status (reference). §7.9: the copy note appears only after `c`; Esc leaves "Print page: <outcome>.". Ctrl-R hiding the password clears the form message.
68. **tui.md §11.7 vs cli.md §1.4, a signal in the standalone form (`passh edit`).** cli.md says a signal at any other moment ends passh by its default action; the form restores the terminal first and passh then exits 128+n.
69. **Not in the spec, reference behaviour reproduced:** the TUI enables the kitty keyboard protocol and xterm modifyOtherKeys (to tell Ctrl-Backspace from Esc) and disables them at exit.
70. **Copy countdown replaced by another message:** the later "Clipboard cleared." is not shown; a failed clear always is (decided).
71. **Display widths are per code point** (print.md §3.2 rule), not per grapheme cluster: a ZWJ emoji sequence can shift borders in some terminals — same as the reference.

## Agent (agent-session.md §A2)

72. **§A2.3 (c), core dumps failing in the child.** No text given. Decided: readiness `error: agent: disabling core dumps: <OS error>`.
73. **§A2.3 (d), "parse exactly".** Reference: Go's `flag` package rules and texts (`--vault X` and `-vault=X` both work; last value wins; `--` ends flags; `flag provided but not defined: -foo`, `invalid value "bad" for flag -idle-ttl: parse error`, `flag needs an argument: -vault`, `unexpected argument "x"`, `--vault must be an absolute path` checked before the TTLs, `--idle-ttl and --max-ttl must be positive`, `resolving the vault path: <err>`). Reproduced. Since §A2.3 calls the parent–child channel informative, this only matters for running the child by hand.
74. **§A2.3 (e), stdin checks.** Order and texts unspecified. Reference reproduced: > 511 bytes → `the key on stdin is too long`; nothing → `the key on stdin: nothing was sent`; > 2 lines → `the key on stdin: unexpected extra lines` (before the key check); `… not a vault key` / `… not a valid vault key`; one line → `the key block digest is missing on stdin`; bad digest → `the key block digest on stdin is not a SHA-256`. Lines trimmed with Go's TrimSpace (so NBSP is trimmed).
75. **Readiness `error:` texts.** Reference: folder errors carry no `agent: ` prefix, bind errors do; the parent strips one leading `agent: ` as specified.
76. **§A2.3, "started but doesn't answer".** The child is killed (decided); for "no agent" the cause reads `its socket is gone`. A readiness line that isn't `ok`/`running`/`error: …`: `agent: starting the agent: unexpected readiness line "<line>"` (decided).
77. **§A2.3 step 6 (`running`).** The `--ttl` warning is printed too (decided); a winning agent that answers `key_block_changed` is an error; one that vanished: `starting the agent: another agent started meanwhile and exited` (decided).
78. **§A2.3 step 2 — the spec omits a request.** Reference sends `status` → `key` → `status`, so `<times>` are reported after the key request restarted the idle time; a failing second status ends unlock with an error. An expired or vanished agent also gets the "replacing it" note and a stop with `lock`'s wait. The parse failure reads `an agent is running, but the vault can't be checked against it: <abs>: not a passh vault` (lenient-parse warnings not printed). Reproduced.
79. **§A2.5 `key_block` "present".** Reference: an empty string counts as missing; `null` keeps an earlier value (Go's decoding). Key-text rule: `AGE-SECRET-KEY-1` must be followed by at least one `[A-Z0-9]`. Client: `v` is decoded in a first pass, so `{"v":2,"ok":"x"}` gives the version error, not "malformed"; a missing `ok` gives `the agent refused the request: ` with an empty text. Reproduced.
80. **§A2.7 connect errors.** Reference: `agent: connecting to <p>: dial unix <p>: connect: permission denied`; a folder or regular file at the socket path gives ECONNREFUSED → no agent. Decided: a connect timeout reads `…: dial unix <p>: i/o timeout`; ECONNRESET with the path still present reads "closed the connection without answering". Bind failures other than EADDRINUSE: `agent: listen unix <path>: bind: <reason>` (decided).
81. **§A2.9, `lock` timeout text.** Reference: `agent: waiting for the agent (pid n) to exit: context deadline exceeded` (Go's context text).
82. **§A2.8, `verify --full` order.** Reference: a `key_block_changed` from the configured vault's agent is silent; each warning names its own file; a file reached twice (by real path) is asked once.
83. **`<file>` in `Unlocked …` / `No agent is running for …`.** Reference: the vault path as configured (not the real path), in `~/` form. Doctor: with a failing folder check the `agent` row is absent; `<dir>` in `~/` form.
84. **A signal before readiness** (decided): readiness `error: agent: interrupted`, exit 1.
85. **Audit #2, #25:** current behaviour kept. **#26** (a copy of the key in an unwipeable string): fix implemented — the child's stdin is built from wiped bytes. (A JS string of the key still exists briefly in the child and the client while parsing.)
86. **Bun: the socket path.** `Bun.listen({unix})` and `node:net` unlink the path they bound when the listener stops — even if it now holds another agent's socket. passh-ts binds a temporary name in the 0700 folder, chmods it 0600, and renames it into place with no-replace (EEXIST stands for EADDRINUSE). Externally identical.
